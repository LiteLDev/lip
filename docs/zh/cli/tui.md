# 交互界面

在终端里不带参数运行 `lip`，即可打开交互界面：lip 的全部命令、[levimc.org/mods](https://levimc.org/mods/) 上的模组，以及工作区的服务器，都在一个全屏程序里。

```shell
lip
```

界面一次处理一个工作区，起初是当前目录（见[工作区](#工作区)）。当 lip 的标准输入或标准输出不是终端时（脚本或管道中），不带参数的 `lip` 仍然输出帮助。

与命令一样，界面运行在 lip 的[守护进程](../guides/internal_mechanism.md#守护进程)中；你启动的 `lip` 负责显示它并转发你的按键。你可以同时在多个终端中打开它。

## 工作区

顶行显示所选的工作区。每个标签页都处理它：包、服务器、配置文件以及 Develop 标签页的命令，都是所选工作区的。

lip 把你用过的工作区记在一个列表里，即其状态目录中的 `workspaces.json`（Windows 上为 `%LOCALAPPDATA%\lip\State`，其他系统为 `$XDG_STATE_HOME/lip`）。界面打开时，当前目录若不在列表中会被加入，并被选中。按 `w` 打开列表：

| 按键 | 作用 |
| --- | --- |
| `↑`、`↓`、`Enter` | 选择一个工作区。 |
| `a` | 添加一个目录（绝对路径，或相对于所选工作区的路径）并选中它。该目录必须存在。 |
| `d`、`Del` | 把选中的工作区从列表中移除。其中的文件都不会改变。当前所选的工作区不能移除。 |
| `Esc` | 关闭列表。 |

列表在 lip 的多次运行之间保留，并由同时打开的各个界面共享。已不存在的工作区会被标记为缺失。

## 标签页

用 `Tab` 和 `Shift+Tab`，或标签页的数字切换。屏幕最下面一行始终列出当前可用的按键。

| 标签页 | 作用 | 对应命令 |
| --- | --- | --- |
| **1 Packages** | 列出已安装的包；安装、更新、卸载。 | [`lip list`](./commands/list.md)、[`lip install`](./commands/install.md)、[`lip update`](./commands/update.md)、[`lip uninstall`](./commands/uninstall.md) |
| **2 Browse** | 搜索、筛选、排序 levimc.org 上的模组，查看详情、版本和 README，并安装。 | [`lip install`](./commands/install.md) |
| **3 Server** | 在窗口里运行工作区的服务器，显示它的输出，并把你输入的行发给它。 | [`lip run`](./commands/run.md) |
| **4 Config** | 查看和编辑 `server.properties`、`allowlist.json`、`permissions.json` 以及已安装模组的配置文件。 | |
| **5 Settings** | 查看和修改用户配置与工作区配置；清理缓存。 | [`lip config`](./commands/config.md)、[`lip cache clean`](./commands/cache_clean.md) |
| **6 Develop** | 创建 `lip.toml`、迁移 `tooth.json`、打包 ZIP、查看包。 | [`lip pkg init`](./commands/pkg_init.md)、[`lip pkg migrate`](./commands/pkg_migrate.md)、[`lip pkg pack`](./commands/pkg_pack.md)、[`lip pkg view`](./commands/pkg_view.md) |

按 `q` 或 `Ctrl+Q` 退出。`w` 打开工作区列表。

## 安装、更新与卸载

对工作区的每次修改都会先生成计划：lip 先以 dry run（`--dry-run`）执行一遍，并显示将要做什么。在你选择 **Apply** 之前，什么都不会改变。

执行修改期间，按 `Ctrl+C` 可以取消，并撤销已经完成的部分。命令失败时，界面会显示原因、可以采取的措施，以及 `.lip/logs` 下失败报告的路径，然后继续运行。

在 Packages 标签页的安装对话框（`i`）里，包的写法与命令行相同（见 [`lip install`](./commands/install.md)），以空格分隔。

当某次安装会设置游戏时，例如在新工作区中安装 `LeviLamina`（见 [`lip setup`](./commands/setup.md)），你选择 **Apply** 后，lip 会在对话框中给出 Minecraft EULA 和 Microsoft 隐私声明的链接，询问你是否接受；除非你接受，否则什么都不会改变。若这种安装的计划中列出了因无法与新游戏配合而将被卸载的 mod，选择 **Apply** 即会卸载它们。

## 浏览模组

Browse 标签页在第一次打开时读取 levimc.org 的模组目录（`https://levimc.org/api/v4/mods/`）；目录内容不会写入磁盘，也不经过 `github_proxy`。lip 只管理服务端，所以列表里只有带服务端构建的模组。

| 按键 | 作用 |
| --- | --- |
| `/` | 按名称、id、作者、标签和描述搜索。`↑` 和 `↓` 进入搜索结果；`Esc` 清除搜索。 |
| `s` | 切换排序：相关度、星标、最近更新、最新发布。 |
| `←` | 进入筛选栏；`→` 或 `Esc` 返回。 |
| `Enter` | 安装选中的模组：先选择变体和版本。 |
| `r` | 显示它的 README。 |
| `o` | 在浏览器中打开它的页面。 |
| `R` | 重新读取目录。 |

筛选栏按筛选的种类分成几个板块：游戏版本、标签、其他标签、许可证、依赖。每个板块默认只显示标题，在标题上按 `Enter` 才展开；标题上会显示其中选中了几项。

| 按键 | 作用 |
| --- | --- |
| `Enter`、`Space` | 在标题上：展开或折叠这个板块。在条目上：包含它。 |
| `←` | 在条目上：回到所属板块的标题并折叠。 |
| `x` | 排除选中的行（仅限标签和依赖）。 |
| `c` | 清除全部筛选。 |
| `→`、`Esc` | 回到模组列表。 |

列表随即只保留满足以下条件的模组：支持任一所选游戏版本，带有全部包含的标签且不带任何排除的标签，许可证属于任一所选的许可证类别，依赖全部包含的包且不依赖任何排除的包。标签和许可证类别与 levimc.org/mods 一致。

在模组上按 `Enter` 会打开一个对话框，同时选择要安装的变体和版本。`←` 和 `→` 切换变体（只列出有服务端构建的变体），下面是最新版本和目录里该变体的每个版本。按 `c` 改为输入自定义版本，即包名 `@` 之后的部分：版本号、`branch:<name>`、`tag:<name>` 或 `rev:<commit>`。之后和所有修改一样，先显示安装计划。

## 按键

同样的按键在各处作用一致：

| 按键 | 作用 |
| --- | --- |
| `↑`、`↓` | 选择一行。 |
| `←`、`→` | 在标签页的各栏之间、对话框的按钮之间、模组的变体之间移动。 |
| `Enter`、`Space` | 对选中的内容执行操作：打开包的操作菜单、安装模组、编辑设置、运行动作、选择按钮。 |
| `Esc` | 返回：关闭对话框、离开当前栏、清除搜索。 |
| `Del` | 卸载选中的包、重置选中的设置、移除选中的玩家，或撤销选中属性的修改。 |

在 Packages 标签页，对包按 `Enter` 会列出可以对它做的操作。在 Settings 标签页，对 `github_proxy` 按 `Enter` 并留空，会让 lip 直接连接 GitHub，而 `Del` 会移除该键；`→` 移到缓存栏，在那里按 `Enter` 清理缓存。在 Server 标签页，服务器未运行时 `↑` 和 `↓` 滚动日志，运行时 `Esc` 清空正在输入的行。

所有列表都是循环的：在第一行按 `↑` 跳到最后一行，在最后一行按 `↓` 跳到第一行。

## 配置服务器和模组

Config 标签页左侧列出工作区的配置文件，右侧显示选中文件的条目。`Enter` 或 `→` 进入条目；`Esc` 或 `←` 返回。

| 文件 | 编辑方式 |
| --- | --- |
| `server.properties` | 逐项列出属性，下方显示选中属性的注释。`Enter` 切换 `true`/`false` 属性，列出只有几个可选值的属性的可选值，其他属性则输入新值；整数会被检查。`Del` 撤销修改。 |
| `allowlist.json` | 允许进入服务器的玩家。`a` 按名称（可选填 xuid）添加；`Enter` 设置该玩家能否在服务器满员时加入；`Del` 移除该玩家。 |
| `permissions.json` | 每个玩家（按 xuid）的权限。`a` 添加玩家；`Enter` 选择 `operator`、`member` 或 `visitor`；`Del` 移除该玩家。 |
| 模组的 `.json` 文件 | 树形编辑：`Enter` 打开对象或数组、编辑值（`true`/`false` 直接切换），`Esc` 返回上一层。在数组中，`a` 添加值，`Del` 移除值。模组文件顶层的 `version` 不可编辑：它由模组自己维护。 |
| 模组的其他文件 | 原样显示；请用文本编辑器修改。 |

模组的配置文件是 `mods/<模组>/config/` 中的文件；没有这样的文件时，是 `mods/<模组>/` 下直接存放的 `.json`、`.ini`、`.toml`、`.yml` 和 `.yaml` 文件（`manifest.json` 除外），以及 `mods/<模组>/data/config.json`。

按 `s` 保存选中的文件之前，什么都不会写入。lip 只改动你修改过的内容：在 `server.properties` 中，只改动你修改过的属性所在的行，所有注释都保留；在 JSON 文件中，只改动你修改过的值，并保持成员的顺序（JSON 文件中的注释不会保留）。带着未保存的修改离开文件、标签页或 lip 时，会询问是否保存。`r` 重新读取文件。

服务器和大多数模组会在服务器第一次启动时生成配置文件，所以新的工作区里可能还没有这些文件；`allowlist.json` 和 `permissions.json` 会在你保存时创建。修改在服务器再次启动时生效：服务器正在运行时，请在 Server 标签页重启它。

## 运行服务器

在 Server 标签页按 `Enter`，会像 [`lip run`](./commands/run.md) 一样启动所选工作区的服务器。服务器的输出显示在窗口里，`PgUp` 和 `PgDn` 可以回看。服务器运行期间，你输入的内容是发给服务器的一行，按 `Enter` 发送；`↑` 和 `↓` 可以调出之前输入过的行。

`Ctrl+C` 会向服务器发送一行 `stop`，请它停止。在你启动的服务器运行时退出 lip，会对其中每一个这样做，lip 会等到它们都退出。关闭终端也是如此。

每个工作区有自己的服务器，因此多个工作区的服务器可以同时运行：选择另一个工作区即可启动或查看它的服务器。同时在多个终端中打开的界面共享这些服务器：每个界面显示其所选工作区的服务器，并可以向它发送行或让它停止。

服务器运行期间，其他标签页仍然可用。与 `lip run` 一样，此时工作区没有被锁定，对包的修改在服务器下次启动时生效。
